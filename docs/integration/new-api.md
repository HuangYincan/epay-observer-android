# New API 集成与验收

状态：Draft。目标是维持标准易支付协议，由 epay-go 向 New API 通知，不让 APK 直接充值。

## 配置映射

| 配置 | 来源 |
| --- | --- |
| 易支付 API 地址 | epay-go 对外根地址；测试时指向隔离测试网关 |
| 商户 ID / PID | epay-go 商户中心的 ID |
| 商户密钥 / KEY | 同一商户的 API Key，不是观察器设备 key 或 notify_key |
| 充值方式 | 微信 wxpay；支付宝 alipay |
| 商户回调 | 由 New API 下单时传入并由网关保存，客户端不能替换 |

本轮不部署或配置实际实例。实施时固定 New API 版本／提交，再依据该版本官方文档与源码核对配置名、回调参数、金额和幂等行为，不能依赖“最新版应该兼容”。

## 端到端成功条件

创建独立测试用户与充值单 → 获取网关订单 → 由夹具产生不包含订单 ID 的通知 → 观察器正常队列上报 → 网关唯一匹配并记账 → 网关向下单保存的 notify_url 通知 → New API 验签并只增加一次余额。

分别验证微信与支付宝。重复事件、重复商户回调、首次回调超时、回调响应丢失和进程重启均不能重复充值。金额或签名错误不得增加余额。return_url 跳转成功不能替代后台入账验证。

## 隔离

New API 测试实例、数据库、商户凭据和用户必须独立；不能对生产用户触发合成充值。测试结束保留脱敏证据和版本信息，不在公开仓库提交实例凭据。
