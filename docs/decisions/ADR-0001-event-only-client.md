# ADR-0001 客户端只上报事件

状态：Proposed。背景：当前回调要求订单号，但静态个人码通知通常不具备该信息。

建议：APK 只观察、解析、持久化和认证上报；网关负责匹配、记账和通知 New API。新增 Observer 接口，不让 APK 直接调用支付成功回调，不下发商户 API Key。

理由：手机不能安全决定订单归属；订单竞争、余额和通知幂等必须由服务端统一控制。代价是必须修改 epay-go，不可能只做一个 APK 就形成正确自动充值。

替代：APK 拉取待支付订单再直接回调。未选原因：扩大凭据权限、在手机复制匹配状态、离线／并发时容易串单。最终接受此 ADR 需协议和跨仓库任务评审。
