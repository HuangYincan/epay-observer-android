# ADR-0003 自动充值及同金额冲突策略

状态：目标已确认；具体匹配策略 Proposed。用户明确选择首版目标为自动充值。

决定：正常且符合策略的唯一匹配自动确认。人工核对只处理异常，不将“先人工点击每笔订单”写成首个可用版本的主目标。模拟器验收不得注入订单号绕过匹配。

待决方案：A. 同账户、同 provider、同金额的占用窗口与复用保护；B. 实付尾数分配；C. 可提供额外可信交易标识的其他来源。首选研究 A，但未批准具体 TTL、复用条件和生产适用范围。

核心难题：旧付款可在订单过期后到账；重复通知可能携带新的观察身份；同一应用通知也可能来自聊天。任何有限时间窗都不能自动证明交易归属。无法区分时必须 needs_review，不以最近一单兜底。

接受条件：给出同额并发、迟到、重复、旧单与新单交叠、跨账户和时钟异常的可执行反例与预期。选定方案须同步收银台行为、金额校验、协议、数据库约束与 New API 回调语义。
