# M0 威胁模型与验收映射

状态：M0 review candidate；#6，SPEC-005，2026-10-15。通知是观察证据，HMAC 认证设备，均非支付平台证明。

资产：事件完整性、receiver 绑定、订单归属、商户余额／流水、New API quota、三类分离密钥、用户隐私。边界依次为通知→Android、本地库→网络、设备认证→receiver 授权、事件接收→匹配、网关事务→商户 HTTP 回调、测试→生产。

## 密钥生命周期与候选默认

设备 HMAC key 与旧 notify_key、New API 商户 API Key 完全分离。一次性配对令牌建议 5 分钟、单次数据库消费，仅授权登记的 receiver/env；配对 API 不纳入 events v1，#17/#20 在实现前另列完整契约。TLS 领取的 HMAC 材料短暂进入进程后导入 Keystore；不宣称端到端硬件生成或硬件证明。服务端需可解密的 HMAC 材料，使用独立加密密钥保护，不可只存 hash 后声称可验 HMAC。

撤销立即拒绝所有后续请求（重复 ACK 也先验证授权）；普通轮换允许旧 key 最多 24 小时重叠，紧急撤销无重叠。同设备换 key 不改变事件唯一范围；重装是新 device，旧事件不可重写 device_id 迁移。日志默认 7 天、ACK 身份墓碑 90 天、本地未决队列最多 10,000 条或 32 MiB；上限到达保留现有记录并显示采集受阻。网关审计／账务保留按部署要求另定，不能清理业务幂等约束后恢复自动复用。

以上默认值仅为隔离测试和工程实现候选，不是生产资金风险政策。生产自动确认尚无充足证据，#8 明确保留启用阻塞。
