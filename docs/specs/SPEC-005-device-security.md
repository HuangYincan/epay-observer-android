# SPEC-005 设备绑定与隐私

状态：M0 review candidate。#6；FR-08。完整威胁、候选参数与残余风险见 [M0 威胁模型](../research/M0-threat-model.md)。

## 配对与权限

Proposed：网关生成一次性、短期、受限配对令牌，绑定设备实例、环境和允许的 receiver。APK 显示网关主机和权限后由用户确认。长期设备凭据通过 HTTPS 领取并安全保存，不把商户 API Key、管理员 JWT 或数据库连接交给 APK。

候选配对令牌 5 分钟、普通轮换最长重叠 24 小时、紧急撤销立即生效；请求偏差 ±5 分钟。具体配对 HTTP 契约在 #17/#20 实施前补齐，事件契约已在 SPEC-002。receiver 单活跃设备，binding_version 变化冻结旧绑定事件。重装创建新设备，旧事件不能改 device_id 后上传。收款账号切换须重新核对；无法从通知保证识别切换是明确残余风险，不能假定同一手机就是同一账户。

## Android 本地

密钥使用 Android Keystore 支持的方案；队列与配置禁止云备份携带凭据迁移到另一设备。诊断默认脱敏，不上传完整通知／聊天内容。无关包通知在采集边界过滤；仅在用户显式允许的诊断流程本地暂存必要信息。

## 网络与服务器

HTTPS、正常证书校验、禁止带凭据重定向；不提供生产明文 HTTP 或忽略证书的开关。客户端网关地址变更需重新确认；环境及 receiver 授权由服务端强制检查。设备撤销、速率限制、异常积压与时钟问题必须可见。

## 测试与发布

夹具 App 有独立包名，不冒充真实支付 App。测试凭据与测试 receiver 不允许进入生产账务。Release 验证必须证明没有测试来源白名单、任意金额确认按钮、跳过验签或直接指定订单的入口。

通知身份不是资金真实性证明；需要覆盖伪装聊天标题、伪造到账文案、重复通知、多设备重复观察等威胁。无法防止的风险必须记录并限制自动确认范围，不得在文档中隐瞒。
