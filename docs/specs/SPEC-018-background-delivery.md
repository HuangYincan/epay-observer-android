# SPEC-018 持久后台投递与遗漏恢复

2026-10-16；#23（#24状态子集），承接SPEC-006/011/017。测试完成前不宣称后台可靠送达，更不宣称自动充值。

## 调度与持久边界

固定AndroidX WorkManager 2.12.0（Google Maven官方元数据2026-09-23发布记录，已核对对应POM与源码）；现有SDK/JBR构建，锁定依赖与校验摘要。不使用前台常驻服务、精确闹钟或电池优化豁免。

Room仍是唯一事件队列，WorkManager Data不存事件body、凭据或标识。通知先提交Room，再请求唯一即时工作；启动/配对恢复/手动发送同样触发。即时工作采用KEEP合并突发触发；另一个15分钟周期工作扫描Room，补偿数据库提交与enqueue之间崩溃，以及KEEP结束窗口遗漏。系统限制可能延迟周期，不承诺15分钟内完成。

正式构建使用WorkManager CONNECTED默认约束（含系统公网验证）。fixture构建使用独立source-set的显式NetworkRequest：要求INTERNET/TRUSTED/NOT_RESTRICTED网络能力，不依赖Android公网探测成功，以支持隔离localhost TLS桥；离线时仍不可运行，不放宽TLS/签名/绑定，标识fixture-local-network-v1不得进入Release。这是模拟器隔离网络条件，不能当成正式构建网络恢复证据。工作仅在对应网络连接约束满足时运行，继续使用OutboxDelivery的原字节/新封套/lease事务。每次最多20次发送、最多2分钟循环（单次网络仍受既有超时限制），检查停止信号，不做睡眠重试。按Room最早READY/RETRY时间或IN_FLIGHT租约到期安排独立唯一延迟唤醒；多个工作并发不重复领取有效lease。授权暂停/冲突/终态不会被定时扫描自动恢复。

唤醒工作只触发即时工作；延迟计划在进程内串行重新查询Room并等待持久登记，使用REPLACE更新到当前队列最早时间（不能传入旧worker缓存的due），不会取消正在执行网络的上传worker。周期扫描与即时工作共用投递实现。未完成的租约由后续工作在到期后恢复。遇数据库/调度异常返回WorkManager retry，不能标ACK或删除事件；若下一次唤醒未能持久登记，当前工作不得宣称成功。

应用显式初始化WorkManager，必须先启动受保护配对恢复；worker遇配对恢复进行中时退避，不访问未恢复授权。重启恢复由WorkManager受保护系统组件承担；强停后Android需用户重新启动，不承诺后台绕过强停。应用重新启动补扫描。通知监听恢复不读取旧活动通知来伪造补收。

## 状态与诊断边界

权限、监听连接、配对、队列积压/暂停、最近持久ACK和系统调度限制分开显示；保留“ACK不等于支付/充值”。失联只描述监听连接，不能由HTTP心跳推断通知来源健康。不将异常堆栈、原始通知、密钥或完整绑定标识加入诊断。

## 验收与证据

- BG-01：网络工作约束、唯一合并和周期扫描配置；Room存在事件但无即时enqueue时可通过扫描恢复。
- BG-02：同一队列有限批次、未来重试、过期lease、授权暂停/冲突不会被自动解除；原body/event_id保持不变。
- BG-03：实际进程终止、设备重启、断网恢复后的持久事件最终ACK；ACK丢失不会生成第二事件。分别记录实际调度与测试驱动器，不混淆。
- BG-04：权限撤销、监听断连、强停、Doze准确显示与说明；既有通知身份不被新调度改写。只报告实际AVD结果，不外推真机/OEM。
- BG-05：严格依赖/构建/lint、精确APK组件/权限检查、生产来源与测试CA隔离；不增加网络验签旁路。
