# SPEC-041 有界真实通知到网关的联调接线

2026-10-19；Android #82 / epay-go #26（承接#24），承接SPEC-036。用户要求补齐真实通知识别、订单关联与结算链路。此前订单只读核对发现网关未支付/零回调、New API pending；真实订单号及金额仅在私有证据中保存，不作为测试输入。
2026-10-19后续：SPEC-046以严格v2接线替代本页v1商户核验字段；服务端改核验既有EPay回调接口，Android仅保留四项通知事实。New API保持原样，旧review不自动转换。


## 实现范围

补上productionDebug独有的、默认停止的单次真实支付宝入口；继续使用既有持久身份、配对凭据、签名和不可变outbox。Release及fixture不能启动此入口。网关增加只读准入检查，不注册HTTP启用接口，不修改现有原订单、余额或New API设置。

一轮必须预先具有：已登记的服务端pilot、与当前配对完全一致的非秘密binding、精确分金额、固定parser、私有证据引用；完整模板、聊天排除、通知身份策略、同额归属风险政策、线上New API金额契约须分别核验。缺一项不启动，不以研究样本自动填为已核验。当前历史样本只提供语法研究依据，尚不满足这些条件。

## Android约束

- 开始仅限本机受信测试控制面，不能通过导出的Activity、通知字段、URL或广播启动；无自动恢复/续窗。启动前永久消费独立marker，准备检查不消费。新进程默认停止。
- 最长120秒、最多读取2条固定官方来源新通知的有限标题/text/bigText/样式字段；在读取extras前校验package/opPkg、同user、实际posting UID、versionCode 212310及固定证书。恢复列表不读取正文。超时、断连或停止后不再读取。该入口不写原文、不向网络发送原文；停止后丢弃本批内存预览。
- 来源与会话许可在回调入口冻结，异步Room工作不能借后续启动/换绑取得权限。仅第一次新观察可生成事件；旧记录、恢复、修订、间断/容量异常继续拒绝distinct。会话结束不修改已封存事件，服务端仍独立核对截止与规则。
- 严格全标题语法解析金额，括号只当有界不透明字段，不推断付款人/渠道。正文用确定性的脱敏token骨架与已批准骨架精确比较；不使用`contains(收款)`或宽泛数字提取。摘要、聊天样式/category、额外文本、未知字段形态及未知模板拒绝。该语法匹配本身不证明聊天排除或支付真实性，不能替代准入核验。
- wire保持SPEC-002原字段，不注入订单号/调试提示，不伪造平台流水；source_class始终notification，精确binding与本轮金额不符不出站。受控distinct只在身份策略明确批准的本轮新观察成立，不能宣称长期可靠性或平台验签。

## 网关检查

提供独立只读检查，使用REPEATABLE READ READ ONLY事务，输出稳定的条件/阻塞编号；未知或缺迁移、环境、receiver/binding/device/credential、规则、原订单/通道/商户、截止、历史同额/证据、alias及既有pilot/暂停均阻塞。检查不取得启用权限，不保证之后仍可登记；实际Arm与首次接收仍由原事务/触发器重新核验。禁止由检查调用查单支付接口或迁移/写库。
