# SPEC-032 用户本地启动的扫码收款通知采样

2026-10-18；#75/#33/#42，FR-01/02/07；承接SPEC-031。用户要求继续，确认扫码收款进入指定模拟器支付宝，并自行建立EPay个人收款码通道。本批只准备、运行用户明确本地点开始的一次120秒标题/正文采样，不把通道配置完成当作真实订单确认已接通。

## 范围

- 保留SPEC-031旧`used`标记、证据与隐私边界。独立固定新标记`used-scan-payment-v1`只对应本批一次窗口，不接受任意session ID，不删除/改名/覆盖旧标记。原CLI继续拒绝已消费的旧窗口；仅androidTest显式`scan-payment-once-120s-v1`可选择新标记，APK主界面/Intent不能选择或启动。
- 来源/字段上限/容量/elapsedRealtime截止与脱敏删除沿用SPEC-031；debug APK无网络，不接收商户或回调密钥，生产来源/解析/上报/匹配不变。NLS只处理窗口内回调，不枚举历史通知。
- 只在127.0.0.1运行控制页；精确Host/Origin、fragment私有token、无请求体、无CORS、禁止缓存/嵌入。复用SPEC-028本地控制器的一次启动、设备互斥和保守宿主120秒预算；等待、刷新、重复点击、状态轮询均不能开窗或续窗。
- 用户准备好付款端和既有二维码后本地点开始；预检阶段明确不付款，只有实际Android RUNNING/连接/来源状态新鲜、宿主预算未过期时才显示绿色倒计时。页面显示回调聚合，不显示正文、二维码、密钥、支付记录或账号。确认付款按钮只记录用户反馈时点，不能当平台付款或到账证明。
- 工具不创建生产订单、不发起或确认付款、不调用旧MD5回调，不改通道启停，不自动为New API充值。页面必须明确当前真实匹配未接通，本轮仅采样，不能承诺扫码后自动充值。实际付款始终由用户自行决定与操作；#8归属门槛保持。
- 点开始后的准备阶段仅发送HOME让支付宝离开前台，避免正在显示支付宝时漏掉普通后台通知；不读取屏幕、账号或账单，不复查登录。这是后台请求，不是独立测量前后台/keyguard条件的可靠性验收。
- Android结构化状态仅固定阶段、回调数、剩余秒数、elapsed_ms和来源/连接布尔值。宿主不公开任意instrumentation输出；状态不合法、失联、取消或180秒超时即停止自己的ADB子进程，finally撤权/强停、清理双方原文并审计。进程退出前持有设备互斥；不可因失败自动重开。SIGINT/SIGTERM进入清理。
- 新证据目录、前后固定四笔/总增额30,000,000审计；新标记与旧标记均保留。没有正文则Not exercised；普通消息/关键词/用户确认均不能升级为真实到账、独立交易或自动充值通过。instrumentation影响进程优先级。
