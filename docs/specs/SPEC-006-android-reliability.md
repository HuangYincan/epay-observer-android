# SPEC-006 Android 后台与持久队列

状态：M0 review candidate。关联 FR-02、FR-03；技术选择见 ADR-0004、身份见 ADR-0005。

## 生命周期

通知监听由 Android NotificationListenerService 提供，需用户授权。权限授予、服务连接、网络正常、网关最近 ACK 是不同状态，UI 不得合并显示“在线”。系统断连或权限撤销后提示原因，并采用平台支持方式重连；不能承诺绕过强制停止和 OEM 策略。

启动后应检查绑定状态和本地队列。重启后处理持久事件不等于补回期间未投递的通知；读取当前活动通知可能重放旧内容，需经过专门身份与时间策略。

## 队列

- 解析后的事件先持久化，再发起网络工作；系统通知回调中不做阻塞网络。
- event_id 与原观察上下文稳定保存；重试改变 request_id／发送时间，不改变业务身份。
- 只有服务器持久 ACK 或明确终态拒绝才能结束重试；ACK 丢失按重复事件安全处理。
- 网络异常／429／5xx 使用带抖动退避；401／403／409 应停止并显示可修复原因。
- 事件过期仍需留有解释记录，不能改成当前时间以便匹配新订单。
- 候选队列上限 10,000 条或 32 MiB、脱敏日志 7 天、已 ACK 身份墓碑 90 天；先到上限即告警，保留现有数据，不静默丢弃。无法落盘时显示采集受阻；系统通知没有持久消费 ACK，不能保证观察到落盘间零丢失。服务端未决与账务幂等证据不可按本地保留期限删除。

## 后台调度

选用 WorkManager 处理积压，数据库是队列真相源。落盘与 WorkManager enqueue 不共享事务，启动／恢复／周期扫描必须补调度遗漏；不能只靠当次 enqueue 成功。调度延迟不是实时到账 SLA，首版不承诺固定秒数；不引入无限保活。旧事件不可改 observed_at 逃避 SPEC-003 的时效限制。

## 验收

进程终止、重启、撤权、服务断连、断网恢复、队列数据库异常、磁盘满、服务器限流、时钟漂移、密钥撤销。模拟器 Doze 结果须与未来真机 OEM 结果分开记录。
