# SPEC-012 请求签名与重试决策核心

状态：2026-10-16，#21 的独立可验证子集；依赖 SPEC-002/011。完整 #21 仍依赖 #17 配对凭据与 #20 接收端。本批不添加HTTP入口、证书例外、密钥存储或后台调度。

## 签名

签名器接受从队列读取的原始body及HmacSHA256 SecretKey，不重新序列化JSON、不读取通知、金额或订单。每次 prepare 都复制body、生成新的UUIDv4 request_id、读取新的发送时间；路径固定POST /api/observer/v1/events。返回的签名输入严格按SPEC-002，单LF且无末尾LF。body/header对外只给副本，防止准备后调用者意外改字节。默认日志字符串隐藏body、凭据ID和签名。

key_id与时间在签名前校验；字节范围1..16384。凭据建立时32字节要求属于 #17；签名器接受不可导出的SecretKey，不通过getEncoded强制导出Keystore密钥。JCA异常向调用层传播，不降级为无签名请求。测试可注入时钟/UUID以复现已提交黄金向量；生产默认使用系统时间/UUID，不注入固定值。event_id仅存在原body中，不以request_id替换。

## 纯重试决策

- 网络异常、5xx、无有效ACK的2xx：重试；429尊重Retry-After并退避。
- 401：暂停凭据修复；403：暂停授权/绑定修复；409：事件冲突隔离；400/413/415：终态诊断。
- 3xx：暂停并诊断重定向，不跟随、不转发凭据。其它非协议HTTP结果暂停检查，不默认当成成功。
- 有效200/202 ACK结束发送（仅持久接收）；调用方必须先通过ACK解码与事件关联验证，布尔参数本身不是验证器。
- full jitter 上限按尝试数：首尝试失败10秒，随后指数上升，最大1小时；Retry-After晚于退避时使用它，不用1小时上限覆盖服务器等待。
- Retry-After支持无符号十进制秒或IMF-fixdate（GMT）；日期过去返回现在。拒绝负数、超长/溢出、不合法日期；超出协议可表达时间的等待暂停人工检查，不能溢出成立即重试。数字溢出饱和到协议最大时间，保守等待。
- 计算不修改队列、body、event_id、observed_at；由后续发送适配器根据lease token原子应用结果。request_id/sent_at不持久化进业务body。
