# SPEC-004 自动充值、事务与回调

状态：Draft。关联 FR-04、FR-05、FR-06。

## 正常路径

合格事件被唯一匹配后，无需逐单人工点击，即完成网关支付确认，并通过现有易支付商户通知使 New API 自动充值。人工核对只处理异常；首个可用测试版本必须展示正常路径全自动完成。

## 事务边界

事件绑定／消费、订单状态、支付确认凭据、商户余额与资金流水必须在同一数据库事务中提交。并发处理同一事件或同一订单只能有一个事务产生收入。不能先调用现有独立提交的 ProcessPayNotify，再另一个事务标记事件已消费。

需定义统一锁顺序以及事件和订单唯一约束。事务异常时全部回滚；进程在任意步骤退出后重试不重复收入。真实平台流水不存在时，单独保存 observer evidence 类型及稳定关联，不能将本地事件 ID 声称为真实交易流水。

## 商户通知

数据库提交后由可靠任务发送通知，或原子登记 outbox 后发送；必须保证提交后崩溃也能恢复，不能仅依赖一次内存 goroutine。通知金额、商户订单号、商户凭据使用原订单保存值，不能让 APK 指定。

回调失败只重试通知，不重新记账。New API 测试实例需验证同一商户订单重复回调、金额不符、签名不符和乱序情况下余额行为。浏览器 return_url 只负责跳转，不作为支付成功证据。

## 可追踪状态

Observer accepted、matched、gateway credited、merchant notify pending／succeeded／failed 分开存储并可查询。测试验收必须同时查看事件、网关订单、资金流水、商户通知和 New API 余额，不能只看支付页面返回成功。

## 异常

匹配歧义／证据不足进入 needs_review；核对需要查看实际收款账单。重复事件不重新开单，不覆盖已确认不同凭据，不恢复已退款订单。测试模式和生产模式各自隔离，测试事件不能进入真实账务。
