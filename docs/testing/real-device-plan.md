# 真机双渠道验证计划与准入门槛

2026-10-16；#35；SPEC-027 READY-01。**计划已定义，实际设备验证Not run。** #33模拟器真实App调查仍独立进行；不能把API37合成通过记作任一真实App/设备组合通过。

## 需要准备的最少信息

- 一台专用测试安卓机：型号、OEM、Android/API、安全补丁版本；不公开硬件序列号/广告标识。
- 微信和支付宝各自的准确版本、获取渠道、应用包名与签名证书核查结果；是否普通个人资料/工作资料/分身。
- 用户自行登录的测试账号，以及是否允许采集脱敏样本。收款账号标识与付款人信息只留本地，不贴公开Issue。
- 实际收款若需要产生样本，另行明确授权每个渠道的金额上限、次数、参与账号和停止条件；当前没有该授权，不执行真实付款。
- 测试端点、设备绑定及日志保管人；初始只做观察验证，不启用生产自动确认。

尚缺上述资源/许可时标Blocked并继续无资金的计划和代码准备，不写Passed。来源解析/签名信任注册需要先补具体Spec和合成回归；当前production规则为空，不能假定安装现有Release就能读取真实收款候选。

## 分阶段门槛

| 阶段 | 需要的证据 | 退出条件 |
| --- | --- | --- |
| D0 来源与环境 | 官方来源安装、固定版本/签名、登录限制、系统权限与监听 | 微信/支付宝分别记录可行性；不使用Hook、包签名伪装或登录绕过 |
| D1 只观察 | 获准样本的字段、通知类别、key/更新时间、缺失字段、解析正负例 | 正例金额以整数分匹配独立原记录；负例无候选；来源或账号不明则停止自动用途 |
| D2 后台与恢复 | 下表在同一指定设备上的逐项运行结果 | 漏投、延迟、重复明确量化；恢复不补造未投递通知、不改原event/body |
| D3 订单归属 | #8明确选择的可靠交易/订单关联证据，以及同额/迟到/重复/跨账户反例 | 仅“唯一同金额待支付单”不算归属证明；无安全金额复用依据保持关闭 |
| D4 受控小额试验 | 单独授权、已通过前三阶段、隔离New API账户、逐笔账单和审计 | 通知/网关收入/回调/topup逐笔对应且一次；任何未解释变化立即暂停 |
| D5 扩大使用 | 长时间监控、升级回归、备用设备/凭据恢复、发布检查 | 新OEM/系统/App版本重新单独验收，不继承旧组合结论 |

D0–D2成功不自动解除D3，不因用户方便或演示需要降低归属标准。永久金额claim仅为当前合成原型限制；有限冷却期和随机/最近订单不能替代真实归属。

## 每个渠道都单独执行的矩阵

| 维度 | 场景 | 观察/通过条件 |
| --- | --- | --- |
| 正例 | 普通收款、最小合法精度、合法较大金额 | 与独立原记录一致；没有平台交易号就保持缺失 |
| 负例 | 聊天提金额、支出、退款、推广、群摘要、冲突金额、畸形字段 | 不自动入账；固定可解释原因 |
| 通知身份 | 同key重复、同key内容更新、折叠/展开、新key同内容、两笔相同金额 | 不把通知键当交易号；歧义保留，不制造第二笔收入 |
| 时间 | 前台、后台、锁屏、系统节电/Doze、长时间闲置 | 记录实际投递/观察/接收时间和缺口，不用手工唤醒掩盖延迟 |
| 网络 | 离线、恢复、TLS错误、服务重启、ACK丢失 | 原事件/字节/ID保持；重试新封套；ACK不代表充值 |
| 生命周期 | 普通进程结束、强停后用户重开、手机重启 | 明确区分系统行为；未重开前结果据实记录 |
| 权限 | 撤销通知读取、重新开启、监听断连 | 权限/连接分别提示；无权限期间不声称补回全部通知 |
| 身份变化 | App切换账号、设备换绑、凭据轮换/吊销、应用重装 | 无法验证收款账号变化时暂停receiver；旧UNBOUND不补绑 |
| 设备边界 | OEM省电设置、工作资料、多开/分身、多用户 | 当前不支持的组合明确Unsupported；不默认识别隔离账户 |
| 升级 | 系统/App/观察器升级、通知文案变化 | 保存原证据；新规则单独回归，不静默重解释历史 |

不同渠道不得用另一渠道通过替代。计划不要求用户主动关闭系统保护或添加全局电池白名单来得到好看结果；若某设备必须特殊设置，要作为独立受限配置写入报告。

## 样本与证据

使用本地私有目录保存原始样本，最小化保存内容和时间；公开库只提交经用户允许的脱敏或等价合成回归。不能采集其他App的无关通知。每项记录环境版本、场景、时间、次数、预期/实际、是否人为打开应用、数据库变化、证据层次和限制。摘要不得含真实账号、付款人、token、设备ID或原通知。

默认建议每个关键正例/重复/后台场景至少重复3轮；这是本项目计划值，不是已验证的可靠性保证。出现漏投/误解析/误归属即Fail，不能以随后成功抵消。

## 停止与恢复

发现账号变化、未知规则、时钟异常、重复收入或额度差异时，先按receiver暂停自动确认，保留接收/证据；必要时吊销设备绑定。独立核对真实账单、网关事件/收入及New API topup；不得清库/释放claim/改event_id重试。恢复只作用于未来合格观察，历史待核对不自动升级。
