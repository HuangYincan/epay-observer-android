# 安卓模拟器优先测试计划

状态：EMU-01..14 通知／充值场景仍 Not run；#9/#5 已获准使用已有 API 37 AVD 验证基础应用。启动、网络与应用重置结果见 [首批报告](M1-foundation-report.md)，没有部署网关或操作支付账号。

## 测试层次

| 层次 | 证明什么 | 不能证明什么 |
| --- | --- | --- |
| JVM／纯解析单测 | 给定样本的规范化与解析结果 | 系统通知投递和真实文案 |
| AVD + 夹具 App | 权限、服务回调、持久队列、上报、生命周期 | 真实微信／支付宝的通知格式与可投递性 |
| AVD + 真实支付 App（若可行） | 该镜像与应用版本组合下的行为 | 所有手机或正式收款稳定性 |
| 实体真机 | 指定设备与 App 版本的真实到账行为 | 其他 OEM 和未来版本 |

## 环境计划

开发基线为 Medium_Phone_API_37.0、API 37.0、Google Play arm64-v8a revision 6；最低 API 29 与 35/36 是后续扩展候选，未安装或运行对应产品测试。

测试拓扑：Observer test build + 独立 fixture → HTTPS 测试网关 → 测试 PostgreSQL → New API 测试实例。fixture 不带订单信息，只有正常通知金额/语义，网关执行完整 SPEC-003 匹配。Release 不含测试信任或 TLS 绕过。AVD 可经测试域名访问网关；10.0.2.2 仅是后续开发路由候选，不可作为 safehttp 接受的商户回调目的地。受控公网 HTTPS 回调链路见 [集成文档](../integration/new-api.md)。

## 证据

每次报告记录 git SHA、APK hash、AVD API／镜像／ABI、宿主平台、网关与 New API 版本、场景 ID、预期、实际、执行时间和脱敏证据。报告必须包含失败与 Not run 项；不能只附一张成功截图。

模拟器真实支付 App 无法登录或不投递通知时如实记录 Blocked；继续夹具验证，不以 Hook、伪造包签名或放宽生产匹配规则作为替代。
