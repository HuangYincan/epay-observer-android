# 支付宝本地开始控制页

2026-10-17；#33 / #42；FR-01 / FR-02 / FR-07；SPEC-028 LOCAL-01..04、LIVE-01..03。解决聊天提示到达与两分钟观察窗口错开的协调问题，沿用PR #66的计数驱动；不扩展正文、付款或生产收款范围。

## 用户操作

代理准备并打开这台电脑浏览器里的本地页面，不是模拟器里的网页。页面初始为“准备好后再开始”，没有instrumentation或通知观察。长时间等待或重开支付宝后，先由用户确认模拟器支付宝仍已登录；自动预检只检查进程和通知权限，不检查账号会话。用户准备好另一端消息后：

1. 点“开始这一次测试”，等自动检查结束。尚未变绿时先不要发。
2. 页面变绿、显示“现在发1条普通消息”并有剩余秒数时，发送1条普通支付宝聊天消息，不转账或付款。
3. 可在同页点“我已发1条”记录确认时点；它只是用户反馈，不是平台发送时间或收款证据。页面自动显示回调数，结束后停止并审计，不用回聊天里赶时间。

点击后才开始准备/开窗；刷新、状态轮询和重复点击不会重开。一次控制会话最多一个120秒窗口，结束/取消后不能在原页面再开。失联、状态超过12秒未更新或倒计时结束后收起发送提示；网络请求失败也不自动重发开始指令。用户可点“停止观察”。控制页不是支付宝聊天端，不会替用户发送消息。

“可发送秒数”取设备剩余时间和启动驱动前开始的120秒宿主预算的较小值。驱动启动会消耗部分宿主预算，页面通常从小于120的值开始显示；这是保守提示，不延长实际计数窗口。即使ADB把旧armed状态延迟送达，也不能重新给用户120秒发送期限。

## 代理准备与运行

仅使用既有SDK/已安装的probe主APK及PR #66测试APK，不启动第二AVD。专用qemu/用户0、支付宝运行且非强停、POST_NOTIFICATIONS及AppOp允许、探针监听权限和原系统条件均由点击后的预检复核；来源版本/签名继续由Android驱动固定核对。没有登录界面或正文读取。

代理须先确认上一次观察已终止，不得同时运行其他设备驱动。每个模拟器只有一个本地控制器持锁；用户点开始明确开始新一次计数，预检及固定四笔审计通过后先重置探针旧进程，再唤醒屏幕并启动自己的单次instrumentation。重置只以内存中的PID比较确认旧进程已退出，不导出PID，也不要求获得监听授权的进程持续消失。系统重建的新进程按既有主APK默认停止；这不是直接读取新进程内存状态的额外验收。页面等待本身不启动采集。

```sh
python3 scripts/probe_delivery_avd.py emulator-5554 \
  --lab /tmp/epay-observer-accept-20261016-143716 \
  --directory /tmp/observer-probe-local-NEW-UNIQUE-RUN
```

目录必须全新且私有。程序只绑定127.0.0.1随机端口，将控制URL及宿主PID保存到该目录`control.json`，不在控制页状态或请求日志中输出令牌；代理从该文件打开页面，不提交文件。令牌在URL fragment中进入页面，再从地址栏移除，刷新通过当前标签页的sessionStorage保留；控制令牌只授权本次本地窗口，不是商户或设备凭据。

Host必须为精确环回地址/端口；开始、确认及停止请求须同源、持有令牌且无请求体。不提供CORS、任意命令、文件读取或自由参数。页面仅呈现固定状态、聚合计数及结束结果，不呈现原始命令输出、账号、通知或设备标识。

准备上限90秒，instrumentation上限180秒。取消/退出/超时/异常均进入清理，停止自己的驱动并重置探针旧进程，恢复原屏幕状态，复核原锁屏/网络/权限/电池/Doze并独立审计固定四笔账务；恢复检查上限75秒。没有改过的系统设置仅比对，不覆盖并发外部修改。证据写入失败会停止任务，不能阻止设备清理；恢复或审计失败显示Failed，不以观察到回调抵消。关闭控制器用Ctrl-C或SIGTERM，持有设备互斥直到清理结束，原始证据保留。
