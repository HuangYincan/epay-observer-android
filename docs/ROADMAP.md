## 建议实施顺序

先完成许可证、架构、协议与匹配策略研究；安卓工程／夹具与网关基础模型可在明确契约后分开推进。之后先打通接收与队列，再做数据库事务、匹配和商户回调。最后跑全部端到端故障场景与 Release 隔离检查。

自动充值目标属于 M3 首个可用测试版本，不把逐单人工确认作为替代交付。无法唯一判断的事件必须保留待核对，不能为满足自动目标降低资金正确性要求。

任务与依赖以 [BACKLOG](issues/BACKLOG.md) 及 GitHub Issues 为准；里程碑没有截止日期，不据此承诺工期。用户已授权持续开发；未决业务政策与外部资源保留显式阻塞。
