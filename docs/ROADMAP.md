# 路线图与阶段门槛

状态：规划；无固定工期。所有里程碑开始时均未实现，M0 文档准备不等于其他阶段已开工。

| 里程碑 | 目标 | 退出条件 |
| --- | --- | --- |
| M0 规格与研究 | 冻结首轮需求、信任边界、协议与关键 ADR | 许可证、事件身份、匹配反例、技术栈和跨仓库分工得到结论；规格可实施 |
| M1 模拟器双通道采集 | AVD、APK 工程、夹具、微信／支付宝解析 | 两类通知分别采集；负例拒绝；权限与生命周期状态可见 |
| M2 可靠认证上报 | 设备绑定、协议双方、队列与重试 | 黄金向量一致；离线／ACK 丢失／撤销／越权测试通过 |
| M3 自动充值测试闭环 | 匹配、事务幂等、New API 自动入账 | 两通道无人工点击完整通过；同额／迟到／并发／回滚测试通过；测试与生产隔离 |
| M4 兼容性与发布准备 | 模拟器真实 App 探索、真机计划、运行手册和发布流程 | 实际证据明确；没有真机证据不宣称真实收款可用；发布需另行授权 |

## 建议实施顺序

先完成许可证、架构、协议与匹配策略研究；安卓工程／夹具与网关基础模型可在明确契约后分开推进。之后先打通接收与队列，再做数据库事务、匹配和商户回调。最后跑全部端到端故障场景与 Release 隔离检查。

自动充值目标属于 M3 首个可用测试版本，不把逐单人工确认作为替代交付。无法唯一判断的事件必须保留待核对，不能为满足自动目标降低资金正确性要求。

任务与依赖以 [BACKLOG](issues/BACKLOG.md) 及 GitHub Issues 为准；里程碑没有截止日期，不据此承诺工期。只有用户明确启动后才开始实现。
